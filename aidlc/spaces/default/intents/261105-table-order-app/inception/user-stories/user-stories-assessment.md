# User Stories Assessment

**Decision:** Execute.

**Rationale:** Table Order is user-facing, with two kinds of user and rules that depend on an order's status, such as cancelling, sold-out items and closing a table. Stories turn the requirements in `requirements.md` into journeys that later stages can test.

**Factors considered:**

| Factor | Finding |
|---|---|
| Project type | New web app with five screens |
| User-facing scope | All three features are used directly by diners or staff |
| Complexity signals | Live updates across screens, status rules, and actions that can happen at the same moment |
| Questions asked | None: the personas, priorities and behaviour are already settled by earlier answers |

**Where stories add the most value:**

- The moments where a diner and staff affect each other: a new order, a status change, a cancel, a sold-out item and a closed table.
- The screen states the mockups must show.
- Acceptance criteria the browser tests can check directly.
